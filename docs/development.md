| `docs/` | This guide, [architecture](architecture.md), [gaps](gaps.md), [roadmap](roadmap.md), [quality](quality.md), [attribution](attribution.md), [writing format](writing-format.md); target-app parity in `parity/`, feature notes in `features/` |

## Build and test

```sh
cargo test --workspace
cargo build --release -p kition-layout                     # the headless kit executable
cd web && pnpm install && pnpm engine && pnpm test:flow     # the kit's editor
cargo xtask ci                                             # the gate: fmt, clippy, tests, assets, layers, wasm
```

`cargo xtask --help` lists the other commands (`assets`, `layers`, `wasm`, `parity`, `stats`,
`version`).

Six P0 features are proved by command-level save-and-reopen round trips in
`crates/engine/engine/src/tests_roundtrip.rs`; `features.yaml` and its cases under `cases/` are
the rest of the feature catalogue ([quality.md](quality.md)).

By default the editor's dependencies come from npm: `pnpm install` in `web/` installs the
published `@kition/sdk` and `@kition/tessera` packages at the versions the committed
`web/pnpm-lock.yaml` pins, so no other checkout is needed. To develop against local checkouts
instead, run `KITION_LINK=1 pnpm install` in `web/`: `web/.pnpmfile.cjs` then links `@kition/sdk`
from a kition-sdk checkout (`packages/sdk`) and `@kition/tessera` from a kition-tessera checkout
(`packages/tessera`), by default `../kition-sdk` and `../kition-tessera` beside this repository
(`KITION_SDK` and `KITION_TESSERA` name others). Both packages' `exports` point at their built
`dist/`, so run `pnpm build` in each package first. A package whose folder is not there stays on
npm. The linked install rewrites
`web/pnpm-lock.yaml`; a lockfile changed that way must not be committed.

`pnpm engine` copies fonts from a [kition-fonts](https://github.com/KitionAI/kition-fonts)
checkout next to this repository (or the one `KITION_FONTS_DIR` names).

## Run the headless kit for an agent

`kition-layout` (`bindings/headless`) serves one layout at a time over the Kit Protocol;
kition-sdk's `kition-kits-mcp` turns it into MCP tools (`layout_inspect`, `layout_run`,
`layout_check`, ...) on a workspace folder for any MCP client:

```sh
cargo build --release -p kition-layout     # target/release/kition-layout
# in a kition-sdk checkout:
cargo build --release -p kition-kits --bin kition-kits-mcp
target/release/kition-kits-mcp --workspace <folder> --kit <kition-layout>/target/release/kition-layout
```

How an agent uses the tools is in [agent/guide.md](../agent/guide.md); kition-sdk's
[agent guide](https://github.com/KitionAI/kition-sdk/blob/main/docs/sdk/agent.md) covers the server.

## Take the README pictures

[`web/scripts/readme-shots.mjs`](../web/scripts/readme-shots.mjs) takes the README's editor pictures
(`assets/readme/hero.png`, `see-1.png` … `see-4.png`) with kition-sdk's shared runner
(`tools/readme-shots/`). It opens the showcase sample `layout/community-garden-trifold` in the
development host (`web/dev.html`) at 1440 × 900, device scale 2, in Classic mode, the light theme
and English, and clicks through the editor as a person would. It needs the engine built in
`web/public/` (`pnpm engine`), and kition-sdk and kition-showcase checkouts beside this repository
(or `KITION_SDK` and `KITION_SHOWCASE` naming them):

```sh
cd web
node scripts/readme-shots.mjs            # every picture
node scripts/readme-shots.mjs see-2      # only the named ones
```

Run it with no HTTP proxy set; `CHROME` may name a Chrome or Chromium executable to use instead of
Playwright's. When `pngquant` is installed the script shrinks each picture with
`pngquant --quality 70-90`; a README picture is at most 400 KB. `made-1.png` … `made-4.png` are
copies of showcase samples' `thumb.png` (tideline-magazine-feature, riverside-night-market-poster,
lantern-keeper-novel, swiss-grid-lecture-poster). Every picture has a row in
[attribution.md](attribution.md).

## Publish

Kition ships the kit's package, `kition-layout-<version>.tgz` (the `layout-ui/` folder), a release
asset of this repository tagged `package-v<version>`. It is built on GitHub, never on a developer
machine: the Package workflow (`.github/workflows/package.yml`, which calls Kition's reusable
`kit-package.yml`) builds the commit it is started on, with `gh workflow run package.yml -R
KitionAI/kition-layout`, and publishes the Release with the package's lock entry,
`kition-layout-<version>.json`. Kition pins it with `node scripts/pin-kits.mjs layout` (see
`docs/kits.md` there). A version is published once: bump `version` in `kit.json` to publish a
change.
